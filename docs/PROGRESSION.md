# Progression counters

`ProgressionService` maintains every counter below from engine and
script events. Achievement criteria of type `counter` read the counter
named by `counter`; `script_feature` criteria read the internal
`script_feature:<feature>` counters. All counters are stored in the
save file (save version 3) and default to `0` when a save predates them.

| Counter | Event | Meaning |
|---|---|---|
| `tiles_moved` | `Moved` | Tiles moved, in total. |
| `max_distance` | `Moved` | Maximum Chebyshev distance from `(0, 0)` ever reached. |
| `biome:<id>` | `Moved` | `1` once the biome `<id>` has been visited. |
| `biomes_visited` | `Moved` | Number of distinct biomes visited. |
| `mined:any` | `OreMined` | Ore items mined, in total. |
| `mined:<ore_id>` | `OreMined` | Items mined of one ore. |
| `unique_ores_mined` | `OreMined` | Number of distinct ores mined at least once. |
| `attempts:any` | `MineAttempted` | Mining attempts that rolled the dice (success or `miss`). |
| `attempts:<ore_id>` | `MineAttempted` | Dice-rolled attempts on one ore. |
| `fail:<reason>` | `MineAttempted` | Every non-success outcome, including `miss` and rule failures (`locked_ore`, `tool_too_weak`, `inventory_full`, `nothing_to_mine`). |
| `streak` | `MineAttempted` | Best run of consecutive successful attempts. |
| `fail_streak` | `MineAttempted` | Best run of consecutive `miss` attempts. |
| `sales` | `Sold` | Sales that earned money. |
| `money_earned` | `Sold` | Total money earned from sales. |
| `largest_sale` | `Sold` | Largest amount of money earned by a single sale. |
| `ores_in_one_sale` | `Sold` | Largest number of distinct ores in a single sale. |
| `upgrades_bought` | `UpgradeBought` | Upgrade levels bought. |
| `regens` | `TileRegenerated` | Tiles regenerated by `World.advance`. |
| `scripts_run` | `ScriptStarted` | Scripts started. |
| `scripts_finished` | `ScriptFinished` | Scripts that finished normally. |
| `script_feature:<feature>` | `ScriptStarted` | `1` once a script with that feature starts (internal; used by `script_feature` criteria). |
| `good_estimates` | `EstimateSubmitted` | Estimates judged good (within tolerance). |

## Script features

`scripting/host.py` parses the script with `ast.parse` (never executes
it) and reports a `frozenset[str]` on `ScriptStarted`:

| Feature | Detected when the script contains |
|---|---|
| `defines_function` | a `def` or `async def` |
| `uses_import` | an `import` or `from ... import` |
| `uses_comprehension` | a list/set/dict comprehension or a generator expression |
| `uses_class` | a `class` |
| `uses_try` | a `try` statement |
| `uses_recursion` | a function that calls itself by name |
| `uses_lambda` | a `lambda` |
| `uses_generator` | a `yield` or `yield from` inside a function |

The legacy criteria type `script_defines_function` is an alias of the
`script_feature` criterion with feature `defines_function`.

## Attempts and failures

A `mine()` that rolls the dice is an attempt, whether it succeeds or
misses. A rule failure (`locked_ore`, `tool_too_weak`,
`inventory_full`, `nothing_to_mine`) is not an attempt, but it still
increments `fail:<reason>`. Rule failures do not break a success or
miss streak because they are not attempts.
