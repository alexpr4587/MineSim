# Prompt 11 of 14 (v0.2): progression engine extension

Follow AGENTS.md. Goal: give the achievement system the building blocks the v0.2 achievements need. No new achievements yet (prompt 13 adds them). First read core/events.py, core/engine.py, core/commands.py, core/progression/*, core/save.py and scripting/host.py.

1. Events. MineAttempted(ore_id, success, reason): reason is None on success, 'miss' when the dice rolled a failure, otherwise a rule failure (locked_ore, tool_too_weak, inventory_full, nothing_to_mine). An attempt is a mine() that rolled the dice (success or 'miss'); rule failures are not attempts. Moved carries x and y. Sold carries money and items {ore: count}. New TileRegenerated(x, y), published by the engine when World.advance regenerates a tile. New EstimateSubmitted(ore_id, p, error, attempts, good) (the function arrives in prompt 12). ScriptStarted carries features: frozenset[str].
2. Script features, computed in scripting/host.py with ast.parse (never exec): defines_function, uses_import, uses_comprehension (list, set or dict comprehension, or generator expression), uses_class, uses_try, uses_recursion (a function that calls itself by name), uses_lambda, uses_generator (a function containing yield). The old criteria type script_defines_function stays valid as an alias of the feature defines_function.
3. New counters, all maintained by ProgressionService from events and documented in a table in docs/PROGRESSION.md: max_distance (max Chebyshev distance from (0, 0) ever reached); biome:<id> (1 once visited) and biomes_visited; attempts:<ore_id>; fail:<reason> (every non-success outcome, including 'miss'); streak (best run of consecutive successful attempts); fail_streak (best run of consecutive 'miss'); unique_ores_mined; largest_sale (max money of a single sale); ores_in_one_sale (max number of distinct ores in a single sale); upgrades_bought; regens; scripts_run; good_estimates.
4. New criteria type {type: 'script_feature', feature} (completes when a script is started with that feature) next to the existing counter criteria.
5. New reward types unlock_skin and unlock_example. ProgressionState gets unlocked_skins and unlocked_examples (starting with everything whose unlocked_by is null); the ProgressionView protocol gets is_skin_unlocked and is_example_unlocked (the wardrobe from prompt 10 switches to them). Load-time validation covers the new ids; skip examples validation while examples.json does not exist yet.
6. Save version 3: migrate version 2 and version 1 saves (new counters default to 0, new unlock sets start as described above). Keep a stored version-1 save and a version-2 save as test fixtures.
7. Tests: every new counter and criteria with synthetic event sequences (including the boundary between 'miss' and rule failures); an AST feature table test with one positive and one negative snippet per feature; migrations; all earlier tests still pass.

ACCEPTANCE: a headless scripted session moves every counter in docs/PROGRESSION.md as documented.
COMMIT: feat(core): progression counters, script features and new reward types
